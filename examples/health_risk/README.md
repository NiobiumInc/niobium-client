# Private heart-disease risk check

_Generated by the [Niobium FHE Application Design AI Assistant (FHEanna)](https://www.skills.sh/niobiuminc/niobium-skills/fhe-application-design)._

An interactive example: you type a patient's measurements at a prompt, your
machine encrypts them, a separate risk-service process computes the 10-year
cardiovascular risk **without ever decrypting anything**, and your machine
decrypts the answer. Change one answer ("what if I quit smoking?") and ask
again.

The score is the published **Framingham 2008 office-based (BMI) model**
(D'Agostino et al., *Circulation* 2008). Patient 0 of the test set is the
published test case from the CVrisk R package: male, 55, BMI 30, blood
pressure 140 untreated, non-smoker, non-diabetic → **16.75%**. This example
returns 16.75%.

Unlike the single-shot examples next to it, the service **records the
computation once** (the first question) and **replays the recorded trace for
every later question** on the new encrypted data.

- [DESIGN.md](DESIGN.md) — why it is built this way, the protocol, what each side can learn.
- [RESULTS.md](RESULTS.md) — measured accuracy, timings and sizes.

## Files

| Path | Runs on | Role |
|---|---|---|
| `keygen.cpp` → `health_risk_keygen` | patient | context and all keys (secret key stays here) |
| `encrypt.cpp` → `health_risk_encrypt` | patient | range check, logarithms, slot placement, encrypt |
| `server.cpp` → `health_risk_server` | service | the encrypted circuit; records once, replays per question |
| `decrypt.cpp` → `health_risk_decrypt` | patient | decrypt to a risk fraction |
| `common.hpp` | both | slot layout, input bounds, CKKS parameters, `run_circuit()` |
| `data/model.txt` | service | the 16 slot weights and the risk-curve settings |
| `data/test_patients.csv` | test only | 5,129 test patients with the reference and twin answers |
| `design/reference.py`, `design/twin.py` | design | the published formula, and a plaintext copy of the circuit |
| `demo/risk_server.py`, `demo/risk_client.py` | service / patient | the interactive two-process demo |
| `run_test.sh`, `tools/` | test | end-to-end test runner and its report |

## Build

From the repository root (this checkout must already be configured with
`make release`):

```bash
make build-release
```

The four programs land in `build/examples/`. The design scripts and the demo
are Python 3 standard library only.

## Run the interactive demo

Two terminals, from `examples/health_risk/`:

```bash
# terminal 1 — the risk service
python3 demo/risk_server.py              # --mode sim (default) | cpu | fog

# terminal 2 — you, the patient
python3 demo/risk_client.py
```

What you see (terminal 2):

```

  sent mk.bin (37.8 MB) to the risk service
  sent rk.bin (151.0 MB) to the risk service

  (cross-check computed in the clear on this machine: 16.75%)
```

Terminal 1 shows only byte counts, and whether it recorded or replayed:

```
[risk-service] setup: received rk.bin, 151,007,051 bytes
[risk-service] received 9,439,467 bytes of ciphertext
[risk-service] recorded the trace, then replayed it in 2.06s; returned 1,050,003 bytes, still encrypted
[risk-service] received 9,439,467 bytes of ciphertext
[risk-service] replayed the recorded trace in 2.03s; returned 1,050,003 bytes, still encrypted
```

Values outside the range the model covers (age 30–74, BMI 15–50, blood
pressure 90–200) are refused and asked again before anything is encrypted.
Each client start generates a fresh key set and re-uploads it, which also
clears the service's trace cache.

The service's folder (`run_demo/server_home/`) never holds a secret key. It
refuses to start if one is put there, and it only accepts the four setup files
by name. To run it on another machine, pass `--server http://HOST:8765` to the
client (the service binds to 127.0.0.1 by default; change the bind address in
`risk_server.py` for a remote host).

## Run the tests

```bash
./run_test.sh --cpu        # plain OpenFHE on this machine
./run_test.sh --sim        # hollow record -> local simulator replay (rehearses the Fog run)
./run_test.sh --sim-full   # real-math record -> replay, plus a bit-identical check vs OpenFHE
./run_test.sh              # the Niobium Fog (needs `fog login`; FOG_TARGET=FUNC_SIM for the
                           # hardware-free simulator)
```

By default each run scores one patient (row 0, the CVrisk case). `NREC=100`
scores the first 100 test patients as a **validation sweep**: patients after
the first replay the first one's trace, and the sweep reuses one key set to
stay fast (the deployment uses one key set per patient). `RECORD=5001
NREC=128` sweeps the 128 corners of the input box.

The report leads with the answer, then whether encryption changed it:

```
=== (a) Result: 10-year cardiovascular risk (Framingham 2008, BMI model) ===
  patient    0:  16.748%  (intermediate)   published model  16.748%   [M age 55.0 BMI 30.0 BP 140.0]
  patient 0 is CVrisk's published test case: CVrisk reports 16.75%, this run 16.75%

=== (b) Did encryption change the answer? (decrypted vs the plaintext twin) ===
  worst 0.000035 pp, mean 0.000035 pp (tolerance 0.001 pp), risk-band changes 0
  PASS

=== (c) Deployment profile (cpu) ===
  server        0.92s mean over 1; peak RSS    313.7 MiB
  setup:rk.bin                   151.01 MB
  per-query:ct_x.bin               9.44 MB
  per-query:ct_result.bin          1.05 MB
```

Resources: the server peaks at about 360 MiB of memory with `--cpu` and about
560 MiB with the simulator modes, and each run home takes about 200 MB of disk. Every mode runs at the full 2^16 ring with 128-bit security.

### Where the residual error comes from

| Source | Size (worst, over the test patients checked) |
|---|---|
| Published model, as reimplemented (vs CVrisk's test case) | 0 at CVrisk's two-decimal precision |
| Curve stand-in (twin vs reference) | 0.0001 percentage points |
| Encryption (FHE vs twin) | see [RESULTS.md](RESULTS.md); tolerance 0.001 pp |

## Troubleshooting

- `fhetch_sim failed ... Is the binary on PATH`: `run_test.sh` and the demo
  set `NBCC_FHETCH_SIM` to `build/vendor/niobium-fhetch/fhetch_sim`. The
  installed copy under `vendor/lib/niobium-client/bin/` in this checkout cannot
  find `libnbfhetch` (no `LC_RPATH`), so use the build-tree one.
- `multiplicative depth [N] is insufficient`: `kDepth` in `common.hpp` must
  cover 1 + 1 + `ceil(log2(degree+1)) + 1` for the degree in `model.txt`.
- A stale trace after changing the circuit: delete
  `run_*/server_home/health_risk_server_workload_*` (or `make clean`).
